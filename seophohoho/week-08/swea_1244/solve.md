# SWEA 1244 최대 상금

## 문제 요약

- 숫자판(최대 6자리)에서 두 자리를 골라 바꾼다.
- 정해진 횟수(최대 10번)만큼 **반드시** 바꿔야 한다.
- 만들 수 있는 가장 큰 수를 구한다.

## 첫 시도: 정렬 (`solve0.py`) — 오답

숫자를 큰 순서로 정렬했다. 교환 횟수를 무시해서 틀렸다.

- **횟수가 부족한 경우**: `757148`, 1회 → 정렬하면 `875541`이지만, 한 번으로는 못 만든다. 정답은 `857147`.
- **횟수가 남는 경우**: `94`, 1회 → 이미 최대지만 반드시 바꿔야 한다. 정답은 `49`.

## 알고리즘을 고르는 순서

"완전 탐색 문제"라는 딱지는 처음부터 붙어 있지 않다. 아래 순서로 따져서 정한다.

1. **그리디가 되나 먼저 본다.** 가장 빠르고 코드도 짧다.
   - 그리디(greedy) — 매 순간 가장 좋아 보이는 것만 고르는 방식.
   - "가장 큰 수 만들기"는 보통 앞자리부터 큰 숫자를 채우면 풀린다. 그래서 먼저 떠오른다.
   - `solve0.py`의 정렬도 이 발상이다.
2. **반례를 찾는다.**
   - 반례(counterexample) — 방법이 틀린다는 걸 보여 주는 입력 하나.
   - `94`, 1회 → 남은 교환을 억지로 써야 해서 틀린다.
   - `32888`, 2회 → 같은 8이 여러 개라 어느 8과 바꿀지 정할 수 없다.
3. **반례가 나오면 입력 크기를 본다.** 최대 6자리라서 나올 수 있는 순서는 720개뿐이다.
4. **작으니까 완전 탐색으로 간다.**

결론: 그리디의 정당성 검증(greedy correctness proof)이 실패했고, 상태 공간(state space)이 작아서 완전 탐색을 골랐다.

- 그리디의 정당성 검증 — "매번 최선을 고르면 끝에서도 최선인가"를 확인하는 것.
- 상태 공간 — 나올 수 있는 모든 경우의 모음.

## 다른 알고리즘은?

- **정렬 ✗**: 교환 횟수를 무시한다. `757148`, 1회 → `875541`은 한 번에 못 만든다.
- **그리디 ✗**: 같은 숫자와 남은 횟수 때문에 예외가 너무 많다. 위의 반례 참고.
- **이분 탐색 ✗**
  - 이분 탐색(binary search) — 범위를 반씩 잘라 좁혀 가는 방법.
  - "이 값보다 크면 무조건 안 된다"처럼 한쪽으로 갈리는 기준이 있어야 쓸 수 있다. 이 문제에는 그런 기준이 없다.
- **그냥 DFS (중복 제거 없음) ✗**
  - DFS(깊이 우선 탐색) — 한 갈래를 끝까지 파고든 뒤 돌아오는 방식.
  - 중복을 안 지우면 15¹⁰ ≈ 5,766억 번이라 시간 초과.
- **DFS + 방문 체크 ✓**: (숫자, 몇 번째 교환)을 기억하고 같은 상태는 다시 안 간다. 그러면 BFS만큼 빠르다. 탐색 순서만 다른 같은 풀이다.
- **순열 전부 만들고 검사 △**
  - 720개 순열을 다 만든 뒤 "정확히 k번 만에 만들 수 있나"를 따로 판단해야 한다.
  - 같은 숫자가 있으면 그 판단이 어렵다. 되긴 하지만 복잡하다.

핵심은 **"모든 경우를 보되, 같은 상태는 한 번만 본다"** 이다. 이걸 지키면 BFS든 DFS든 통과한다.

## 해결: 레벨별 BFS + 상태 중복 제거 (`solve1.py`)

BFS(너비 우선 탐색) — 한 단계씩 가능한 경우를 전부 넓게 펼쳐 보는 방식.

1. 처음 숫자를 집합에 넣는다.
2. 집합의 모든 숫자에 대해 두 자리를 바꾸는 모든 조합을 만든다.
3. 결과를 **새 집합**에 담는다. 같은 숫자는 한 번만 남는다.
4. 2~3을 교환 횟수만큼 반복한다.
5. 마지막 집합에서 가장 큰 값이 답이다.

### 예시: `94`, 2회

```
0회: {94}
1회: {49}
2회: {94}   → 답 94
```

## 시간 복잡도

- 6자리 숫자의 순서는 최대 6! = 720가지다.
- 집합이 중복을 없애므로 한 회차의 상태는 720개를 넘지 않는다.
- 한 상태에서 바꾸는 조합은 6C2 = 15가지다.
- 전체: 720 × 15 × 10 ≈ 10만 번이면 충분하다.

## 핵심

- 상태 공간(state space) — 나올 수 있는 모든 경우의 모음. 이 문제는 상태 공간이 720개로 작다.
- 그래서 **완전 탐색(brute force)**, 즉 모든 경우를 다 확인하는 방식이 가장 안전하다.
- 같은 상태를 다시 계산하지 않는 **메모이제이션(memoization)** 으로 폭발을 막는다.
- 메모이제이션 — 한 번 계산한 결과를 기억해 두고 다시 계산하지 않는 것.

## 코드

```python
states = {ns}
for _ in range(cnt):
    next = set()
    for s in states:
        arr = list(s)
        for i in range(n - 1):
            for j in range(i + 1, n):
                arr[i], arr[j] = arr[j], arr[i]
                next.add("".join(arr))
                arr[i], arr[j] = arr[j], arr[i]
    states = next
print(f"#{tc} {max(states)}")
```

- 모든 상태의 길이가 같아서 문자열 `max`가 곧 숫자 최댓값이다.
