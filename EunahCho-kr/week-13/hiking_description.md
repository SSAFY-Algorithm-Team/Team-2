# 문제 이름
- 플랫폼 / 문제 번호: 프로그래머스 / 등산코스 정하기
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/118669?language=python3
- 제출 상태: 해결 (블로그 코드 참고)

## 문제 설명
노드 1 ~ n : 출입구 or 쉼터 or 산봉우리 (입력에 출입구와 산봉우리 번호 주어짐)
간선 : 소요시간
 => 각 지점은 양방향 통행 가능하며, 소요시간이 있음

- 각 노드에서는 휴식을 취할 수 있으며, 휴식 없이 이동해야하는 시간 중 가장 긴 시간을 intensity라고 부름 (즉, 경로 속 간선에 적힌 숫자 중 가장 긴 시간이 intensity임)
- 출구와 입구는 동일하고 산봉우리는 한 번만 포함되어야 할 때, intensity가 최소가 되도록 등산코스를 정할거임
  -> 만약 최소 intensity를 포함하는 경로가 두 개 이상이라면, 더 작은 산봉우리 번호를 출력함

## 입력 예시 
n, paths, gates, summits (노드 개수, 노드와 간선 정보, 출입구 후보지, 산봉우리 후보지) 순서      
6, [[1, 2, 3], [2, 3, 5], [2, 4, 2], [2, 5, 4], [3, 4, 4], [4, 5, 3], [4, 6, 1], [5, 6, 1]], [1, 3], [5]

## 출력 예시
[산봉우리 번호, intensity의 최솟값]         
[5, 3]

## 풀이 방법
- 다익스트라로 접근

**초기 접근**
- 똑같은 길로 돌아오면 되므로 편도만 고려함
- 출입구 후보지 -> 산봉우리 후보지를 이중 for문으로 돌며, 각 경우에 대해 다익스트라 적용
- 기존에 배운 다익스트라는 누적값의 최소를 구하는 방식인데, 이 문제는 지나는 모든 간선이 최대한 작아야함 -> heap에 [intensity, current_node] 넣겠다는 생각까진 함 -> 다만 세부 조건 적을 때 막혀서 블로그 찾아봄

**이후 접근**
- 사용할 객체들 : dist (길이 n이고, 무한대로 초기화된 리스트 / 최소 intensity 저장하는 역할로 쓸 것), candi (최소 힙, [intensity, node번호] 넣어서 사용할 것)
- 출입구 후보지를 heap에 모두 넣고 시작함
- 위의 heap을 while 문으로 돌면서, 최소 intensity와 그 때 노드번호를 pop 받고 연결된 다음 노드를 탐색함
  -> 다음 노드로 가는 weight vs 현재 intensity 중 큰 값으로 intensity 업데이트
  -> 위에서 구한 intensity값이 dist에 저장된 intensity값보다 작으면 dist 업데이트 및, heap에 넣음
- (가지치기) heap에서 꺼낸 intensity가 dist에 저장된 값보다 크면 탐색하지 않음
- (종료?조건) heap에서 꺼낸 노드 값이 산봉우리라면 그 길 탐색은 종료함
- dist 리스트에서 각 산봉우리에 저장된 intensity 중에 최소값 출력


## 코드 설명 (핵심이라고 생각한 것)
- heapq에 시작 노드를 모두 넣음
- heapq에 기존 방식인 [누적값, 노드 번호] 대신 [경로 내 최소 intensity, 노드 번호] 작성 

## 막힌 점 또는 질문
- 시작 노드가 여러개일 때 heapq에 이 노드를 모두 넣고 시작한다는 점이 헷갈렸습니다. bfs에서도 이 방식을 봤었는데도 잘 안떠올랐습니다. bfs의 큐, 다익스트라의 힙에서 한 튜플이 지금까지 경로 정보를 담고 있다고 이해하면 되는지 아니면 더 직관적으로 이해할 수 있는 방법이 있는지 궁금합니다.
- intesity의 정의는 경로 상 가장 큰 간선 값인데, 여러 경로 중에서는 이 intensity값이 가장 작아야해서 이를 정의하기가 어려웠습니다. 이렇게 정답 값에 여러 조건이 달려있을 때 어떤 사고를 거쳐야하는지 궁급합니다.
